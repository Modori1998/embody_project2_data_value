## Constraint probe and decision

Local llama-server 0.6.0-dev build 11577, cbe28bb3c. The exact historical `demo_71-S0003` G1 request from `full_main_r2` was replayed with only `response_format` changed to `{"type":"json_schema","schema":json_schema_v0_2()}`. HTTP 200 and a complete JSON object were returned, yet top-level `evidence_frame_indices` remained absent. The server log generated a generic object grammar (`response-format-schema ::= object`), not a rule enumerating the Schema's required keys. A second diagnostic using `json_object` plus the full Schema happened to include the missing key, but the log again showed the generic object grammar. Neither trial proves field-level constrained decoding. `json_schema` therefore fails this local compatibility gate. HTTP 200 and one valid output are insufficient evidence. The operational protocol is **FALLBACK_JSON_OBJECT_RETRY_V1**, separately frozen here, never represented as Schema-constrained decoding.

The full Schema is always obtained from `semantic_schema.json_schema_v0_2()` for SHA and independent validation. It has 8 required top-level fields, 3 required event fields, enum/type limits and `additionalProperties: false`. No generator option has been demonstrated to enforce those constraints on this build. Exact source requests, responses and server logs are retained locally under ignored `outputs/g3d2r/constraint_probe_v1`; no RGB or private paths are committed.

## Five-arm fallback protocol

Every arm G0/G1/T0/T1/T2 uses `response_format={"type":"json_object"}` and the same retry logic. Retry the same bytes of request, seed, image and prompt. At most 2 attempts for an invalid JSON/Schema/frame-evidence result, and at most 3 attempts for transient service errors. All attempts, including failures, retain their raw response, QC, latency, tokens and GPU sample. The first valid attempt is the final prediction; never select by semantic score. If retries exhaust, mark the cell FAILED and continue to the next cell. Input identity, model or configuration drift causes global STOP. GPU OOM or repeated service unavailability causes a circuit break and resource hold. The pilot passes only if all 20 cells end valid; otherwise the full run is barred. Full starts from a new run directory only after pilot passes and includes all 60 cells anew. The older 44-cell prefix and old pilot cannot be reused.

Reliability measures: first-attempt Schema validity, retry recovery rate, final structural/evidence validity, failed cells and reason, extra attempts, completion/prompt tokens, latency and GPU memory. Semantic scores use the final valid prediction only after all 60 cells have been collected, while first-attempt outcomes remain separately reported. Every group's denominator and retry policy is identical. Semantic threshold remains the original G3D2 pre-registration: T0 vs G0 and T2 vs T0 event micro-F1 at least +0.10; T2 object_motion recall at least 2/3, grasp FP not increased, phase correct count down at most 1, schema/evidence gate. All regressions and five-group scores must be reported. Twelve Development segments are not held out.
