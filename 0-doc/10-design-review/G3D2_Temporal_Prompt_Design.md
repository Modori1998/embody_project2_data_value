# G3D2 Temporal Prompt Design — frozen before first G3D2 model call

Version `G3_TEMPORAL_PROMPT_V0_3_CANDIDATE`. Base v0.2.1 taxonomy, schema, enums, evidence rubric, output fields, event thresholds, Qwen3-VL-4B Q4, mmproj F16, Task, three RGB PNGs, seed 1234, temperature 0, max_tokens 512 and context 4096 remain fixed. This is a Development diagnostic, not held-out evaluation.

The old prompt already includes chronological frames and START/MIDDLE/END labels. Temporal v0.3 changes the actual request content to `[base_temporal_text, frame_label_f0, RGB_f0, frame_label_f1, RGB_f1, frame_label_f2, RGB_f2]`; all frame labels are adjacent to their own image. A generic instruction asks the model to compare f0→f1 and f1→f2 for visible gripper, EEF, object and relation change *before* producing the same JSON. It does not request hidden reasoning or new JSON fields. It states that EEF motion is not proof of object motion, static closure is not grasp attempt, and action commands are not observed outcomes.

Five groups: G0 old v0.2.1 with no state; G1 old prompt plus frozen G3D segment state block; T0 temporal v0.3 with no state; T1 temporal v0.3 plus the *exact same* G1 state block; T2 temporal v0.3 plus two interval-aligned state blocks. T0/T1/T2 share exactly one temporal base text and image-label order. G0/G1 retain old `[full_text, image0, image1, image2]`. No additional RGB.

T2 uses only `load_formal_episode()` policy-visible EEF position, gripper qpos and recorded actions. For each closed RGB interval `[f0,f1]` and `[f1,f2]`, report EEF endpoint XYZ, displacement XYZ and norm, path length, gripper endpoint aperture, actual G1 gripper-state changes strictly after the interval start through its end, and normalized action magnitude over the interval's frame-index-aligned actions. M2 formulas are reused. The middle sample belongs to both interval endpoints; the overlap is explicit, not a claim of two independent motions. Action[t] is aligned to source frame t without shift per P1; it is a command, never proof of achieved motion. State at each of the three RGB indices is a sampled endpoint, not full per-frame state. Missing/nonfinite/identity mismatch stops the request, never becomes zero.

Forbidden: object pose/GT, simulator states, reward, success, done, next_obs, future segments, human labels, historical predictions. Model-visible fields have an allowlist. `gripper_transition_present` from M2 can be true due to a left boundary even when no internal state change; T2 excludes that ambiguous field and reports only actual interval changes.

Pre-registered contrasts: T0−G0 tests the *combined* interleaving+interval-observation prompt change; G1−G0 reproduces segment-state direction; T1−T0 tests old state under temporal prompt; T2−T1 tests interval alignment versus segment state; T2−T0 tests incremental interval state; T1−G1 is descriptive. The combined T0 contrast does not identify the separate contribution of interleaving and instruction.

Pilot gate: four frozen cases × five groups = 20 new calls, all HTTP/JSON/schema/frame valid, 0 cross-boundary, 0 forbidden input, 0 PNG SHA mismatch and request matrix verified. Then 12 Development cases × five groups = 60 new calls. Within each segment rotate five-group order by sample ordinal; same set/order of segments. If substantive predictions vary between runs, repeat all 60 calls under the same frozen design; never select only improving samples.

Development thresholds, fixed before model calls: T0−G0 event micro-F1 ≥+0.10 with phase-correct drop ≤1 and no large FP inflation; T2−T0 event micro-F1 ≥+0.10, object-motion TP ≥2/3 with FP explicitly reported, grasp FP no increase, phase-correct drop ≤1, and all QC gates. Report T2−T1 separately. A gain only nominates an episode-disjoint blind evaluation. Otherwise prefer G3E adaptive RGB keyframes. No post-hoc threshold changes.
